# TAŞIR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the two-player TAŞIR hidden-tile column-shifting game as the third game in the existing browser party hub.

**Architecture:** TAŞIR has an isolated pure game engine under `lib/tasir`, with Firebase/local store adapters matching Ludo's room pattern. App Router pages and a mobile-first CSS module render the lobby, RPS start, hidden boards, shift flow and result without coupling to KADRO or Ludo state.

**Tech Stack:** Next.js 15, React 19, TypeScript, Firebase Realtime Database + Anonymous Auth, CSS Modules, node:test.

**Spec:** `docs/superpowers/specs/2026-09-13-tasir-design.md`

## Global Constraints

- Exactly 2 players; host plays normally.
- 4×5 hidden board per player, four copies of digits 0–9, one Joker.
- RPS decides starter; ties repeat.
- 44px minimum actionable mobile targets; safe-area and 100dvh support.
- Existing KADRO and Ludo state/routes remain independent.
