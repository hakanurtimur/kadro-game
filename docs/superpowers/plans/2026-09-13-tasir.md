# TAŞIR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the two-player TAŞIR 4×5 physical layout but route every opened tile to the lane labelled with its exact value and win only when all five owned lanes are matched 4/4.

**Architecture:** TAŞIR keeps its isolated pure engine under `lib/tasir` and the existing Firebase/local room adapters. The board remains four rows by five columns; each column is now an explicit value lane, so the engine derives the only legal column from the held value. The UI exposes lane labels, symbols, per-lane 0–4 progress, and retains the existing slide/flip/pop animation system.

**Tech Stack:** Next.js 15, React 19, TypeScript, Firebase Realtime Database + Anonymous Auth, CSS Modules, node:test.

**Spec:** `docs/superpowers/specs/2026-09-13-tasir-design.md`

## Global Constraints

- Exactly 2 players; host plays normally.
- 4×5 hidden board per player: five target lanes × four slots.
- Values 0–4 route to seat 0; 5–9 route to seat 1; each value routes to its exact labelled lane.
- Joker is the only free lane choice.
- A win requires all five lanes to be revealed and matched 4/4.
- 44px minimum actionable mobile targets; safe-area and 100dvh support.
- Existing KADRO and Ludo state/routes remain independent.
